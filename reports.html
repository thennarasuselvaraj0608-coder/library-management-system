DBMS Concepts Viva & Demonstration Guide
B.Tech AI & Data Science Project
Project Title: Automated Library Book Tracking and Management System
Technology Stack: Flask (Python), MySQL 8.0, HTML5, CSS3, Bootstrap 5, JavaScript, Chart.js
Database Name: library_management_db (8 Normalized Tables)

All 8 entities are implemented with strict relational integrity:

  • Primary Keys (PK): Every table uses AUTO_INCREMENT PRIMARY KEY for surrogate key identification.
  • Foreign Keys (FK): Cascading and restrict rules maintain referential integrity (e.g., book_issues.book_id -> books.book_id).
  • CHECK Constraints: CHECK (total_copies >= 0), CHECK (available_copies >= 0), CHECK (available_copies <= total_copies), CHECK (year_of_study BETWEEN 1 AND 4), and CHECK (fine_amount >= 0).
  • UNIQUE Constraints: books.isbn, students.register_number, students.email, departments.department_name, categories.category_name.
-- Example Table DDL with CHECK & FK Constraints CREATE TABLE books ( book_id INT AUTO_INCREMENT PRIMARY KEY, title VARCHAR(150) NOT NULL, isbn VARCHAR(20) UNIQUE, author_id INT, category_id INT, total_copies INT NOT NULL DEFAULT 1, available_copies INT NOT NULL DEFAULT 1, CONSTRAINT fk_books_author FOREIGN KEY (author_id) REFERENCES authors(author_id), CONSTRAINT books_chk_total_copies CHECK (total_copies >= 0), CONSTRAINT books_chk_available_copies CHECK (available_copies >= 0), CONSTRAINT books_chk_available_lte_total CHECK (available_copies <= total_copies) );

  • First Normal Form (1NF): All attributes contain atomic (indivisible) values. There are no repeating groups or multivalued columns.
  • Second Normal Form (2NF): Satisfies 1NF, and all non-key attributes are fully functionally dependent on the entire primary key (no partial dependencies).
  • Third Normal Form (3NF): Satisfies 2NF, and no non-key attribute depends transitively on another non-key attribute. Authors, Categories, and Departments are isolated into separate normalized tables instead of repeating text fields.

Demonstrated in view_issued_books_details and view_department_issue_stats:

-- Query combining INNER JOIN, LEFT JOIN, GROUP BY, and Aggregates SELECT d.department_name, COUNT(DISTINCT s.student_id) AS total_students, COUNT(bi.issue_id) AS total_issues_count, COALESCE(SUM(CASE WHEN bi.status = 'Issued' THEN 1 ELSE 0 END), 0) AS active_issues FROM departments d LEFT JOIN students s ON d.department_id = s.department_id LEFT JOIN book_issues bi ON s.student_id = bi.student_id GROUP BY d.department_id, d.department_name HAVING total_students >= 0;

  • Views: view_book_details, view_issued_books_details, view_overdue_books, and view_department_issue_stats simplify complex join queries into virtual tables.
  • Stored Procedures: sp_issue_book and sp_return_book encapsulate multi-step transactions and fine calculation algorithms inside the database engine.

  • Atomicity: Book issuance and copy decrement run inside a single transaction block. If an error occurs, conn.rollback() undoes all partial updates.
  • Consistency: The CHECK constraints and triggers guarantee available_copies >= 0 and available_copies <= total_copies.
  • Triggers: trg_prevent_negative_copies, trg_decrement_copies_after_issue, and trg_increment_copies_after_return automatically sync book quantities.
